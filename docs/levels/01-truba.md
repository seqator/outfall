## 0. Формат схемы

Карта **64×64 тайла** (тайл 64×32 px, `art-bible.md` §2.1). Ось `x`: 0
(запад) → 63 (восток); ось `y`: 0 (устье, старт) → 63 (выход к реке,
финал). ASCII-схемы ниже — обзорные (**1 символ = 2×2 тайла**), для общей
читаемости плана; координаты в таблицах §3–§5 — реальные тайлы (0–63) и
источник истины для OF-025. Ширина проходов ≥5 тайлов, коридоры выровнены
по осям `x`/`y`, без диагональных «бутылочных горлышек» под 45°.

### Легенда

| Символ | Значение |
|---|---|
| `#` | стена / непроходимый бетон, коллизия 1 |
| `.` | пол коллектора, бетон, проходимо |
| `~` | вода (после подъёма затвора), проходимо с замедлением |
| `S` | точка старта игрока |
| `P` | точка панорамной камеры (3–8 с) |
| `?` | плакат «Сброс временно ограничен», декор |
| `V` | задвижка (интерактивный объект сцены 15–25 с) |
| `@` | громкая связь / динамик Санитара |
| `L` | лестница на мостки (высотная точка) |
| `K` | мостки (приподнятая дорожка вдоль восточной стены) |
| `C` | колонна/укрытие (блокирует линию огня, не силуэт) |
| `O` | бочка (взрывоопасный объект) |
| `X` | секрет — тайник за оторванной решёткой |
| `a` `b` `c` | точки спавна раков (см. §4) |
| `R` | Родион «Ключик» Углов, тонущий энергосбытовец |
| `E` | решётка выхода к реке (финал пролога) |
| `Z` | Серёга Сачок, NPC-декор у выхода |
| `1`–`6` | триггеры T1–T6 (см. §3) |

## 1. Схема по зонам (1 симв. = 2×2 тайла)

Тоннель узкий (Зона B) внутри широких залов (A, C, D) — единая сетка 32×32
дала бы нечитаемый разброс пропорций, поэтому схема разбита по зонам,
сверху вниз по порядку прохождения; координаты у каждой зоны — реальные
тайлы (0–63).

### Зона A — Панорама (y 0–9, 3–8 с)

```
y00 ####...P....####
y02 ####...S....####
y04 ####.........####
```

Платформа-«губа» водосброса, `x 18–44`, огорожена низким парапетом. `P`
(30,2) — статичный якорь камеры, смотрит на юг вдоль тела Плотины; `S`
(30,6) — старт игрока, на 2 тайла южнее.

### Зона B — Спуск (y 10–19, 8–15 с)

```
y11 ######...#######
y13 #####?..1#######
```

Пандус вниз, `x 26–34` (ширина 8 тайлов, прямой коридор по оси Y, без
диагоналей). `?` — плакат «Сброс временно ограничен» (26,14), `1` —
триггер T1, подсказка управления (30,14).

### Зона C — Задвижка / смотровая (y 20–29, 15–25 с)

```
y21 ####...........####
y23 ####...2....@..####
y25 ####....V......####
y27 ####~.........L.####
```

Зал шире коридора, `x 16–44`. `2` — T2 (30,22): Санитар по громкой связи
`@` (38,22), открывает сброс; `V` — задвижка (30,24), заклинена (деталь
декора, предвосхищает сцену «Полчаса» из `main-quest.md`); `~` (24,26) —
точка входа воды; `L` (42,26) — лестница на мостки `K` вдоль восточной
стены.

### Зона D — Коллектор-арена (y 30–47, 25–40 с)

```
y31 #######.........K#########
y33 #######........3......K.#
y35 #######...C.......C.c.K.#
y37 #######.a..O...........K#
y39 #######.......C........K#
y41 #######.............C.K.#
y43 #######.X.......b.....K.#
y45 #######..............L..#
```

Главный зал боя, `x 14–46`, прямоугольный, без узких диагоналей. `3` — T3
(30,34), запускает волну раков. Спавны `a` (18,38), `b` (32,44), `c`
(40,36) — три открытых выхода из воды, читаются по всплеску и красному
телеграфу (`art-bible.md` §2.3 п.6). `C` — 4 колонны-укрытия ((20,36),
(36,36), (28,40), (40,42)), укрытие по пояс, не блокируют силуэт. `O` —
бочка (24,38), взрывоопасный объект. `K`/`L` — мостки (высотная точка) и
вторая лестница вниз (44,46). `X` — секрет (16,44), см. §6.

### Зона E — Затопленный коридор / выбор (y 48–55, 40–52 с)

```
y49 ~~~~4~~~~
y51 ~~~~~~~~~
y53 ~~~~R~~~~
y55 ~~~~5~~~~
```

Узкий (`x 22–38`), полностью затопленный — единственный путь дальше, вода
по грудь. `4` — T4 (30,48), запускает сцену выбора и таймер; `R` — Родион
«Ключик» Углов, придавлен решёткой (30,52); `5` — T5 (30,54), фиксирует
исход и флаг.

### Зона F — Выход к реке / крючок (y 56–63, 52–60 с)

```
y57 .........
y59 ...6.....
y61 ...E..Z..
y63 .........
```

Решётка `E` (30,61) открывается в устье, за ней — река и дневной свет
(задник). `6` — T6 (30,58): рация и титр «Глава 1. Труба». `Z` — Серёга
Сачок (36,60), decor-NPC (первая шутка игры, `world-bible.md` §2.1);
диалог — задача narrative-writer.

| 40–52 | E, коридор `x22–38` | `4` T4: вода по грудь, `R` (30,52) — тонущий Родион, таймер идёт; выбор «вытащить» / «снять ключ»; `5` T5 фиксирует флаг | Диалог + выбор (время идёт) |

## 6. Секрет и нелинейный путь

**Секрет.** Тайник `X` (16,44) в зоне D — ниша за полуоторванной решёткой
у западной стены, замаскирована под обычную стену (маркер `X` — служебный,
для дизайнера, не для игрока). Открывается любым способом: `[Взлом]` без
порога, выстрел по бочке `O` рядом (взрыв срывает решётку) или просто
взаимодействие вплотную. Награда — `item.ammo_9mm` ×8 и `item.mat_detali`
×3 (§5) — скромно, чтобы не обесценить открытый бой, но заметно для
внимательного игрока.

**Нелинейный путь.** Мостки `K` (доступ с лестницы `L`, 42,26, зона C) —
обход пути по полу арены. Игрок, поднявшийся на мостки **до** входа в
радиус T3 (30,34), не будит спавн `c` (40,36) — рак не выходит из воды,
пока игрок ни разу не спускался в радиус T3. Раки `a`/`b` всё же могут
заметить шаги на мостках — полный стелс не гарантирован, это риск, а не
чит. Мостки ведут ко второй лестнице (44,46) у края зоны E — полноценный
параллельный маршрут, не тупиковый шорткат. Стандартный путь по полу
остаётся основным и даёт полноценный первый бой, как требует концепт §6.

## 8. Читаемость и бой — проверка по требованиям задачи

- **Укрытия/узкие места**: 4 колонны в зоне D; ширина коридоров ≥5 тайлов
  (B — 8, E — 9, «вода зажимает», но не диагональ и не уже правила).
- **Взрывоопасный объект**: бочка `O` (24,38).
- **Высотная точка**: мостки `K` вдоль восточной стены C/D — обзор сверху,
  недоступен прямому рывку рака.
- **Враги без индикации**: все спавны раков — открытые всплески с красным
  телеграфом, видны с любой точки арены.
- **Чередование темпа**: просмотр 5с → исследование 7с → диалог+событие
  10с → бой 15с → диалог+выбор 12с → крючок 8с — максимум 15с одного типа
  подряд, с запасом от лимита 90с.
- **Первый бой и выбор в первые 2–3 минуты**: оба — в первые 60с игры.

### 11.1 Цель

Игрок должен физически почувствовать «под водой, времени в обрез»: не
читать текст меню в комфортном темпе, а действовать. Ошибка (не успел)
обязана быть честной — понятной по HUD заранее, а не внезапным game over
или зависанием диалога.

### 11.2 Правило и таймер сцены

`trigger_t4` (уже в карте) при первом входе в радиус запускает **таймер
сцены `T_scene = 15,0 с`**, отсчёт непрерывный (не ставится на паузу
диалогом/меню — в этой сцене никакого модального меню больше нет, весь
геймплей идёт в реальном времени поверх обычного управления). 15 с — это
максимум блока «диалог+выбор» по правилу §156 этого документа
(«не более 15 с одного типа темпа подряд»); прежняя оценка «12 с» в
таблице §2/§8 была рабочей прикидкой темпа level-design **до** того, как
появилась сама механика, и заменяется этим числом как приоритетным
(редактировать §2/§8 задним числом не нужно — 15 с укладывается в
исходное правило «≤15 с», разница несущественна для темпа ролика).

Формула отображения:
```
t_remaining = max(0, T_scene − (t_now − t_T4))
```
округление на HUD — вверх до целой секунды (`ceil`).

### 11.3 Исход «Вытащить» (`spas`) — держать E

- Действие: **удержание** клавиши `E` (стандартный `interact`, тот же,
  что открывает диалоги — `INTERACT_RADIUS = 2` тайла,
  `src/game/demo-scene.ts`), пока игрок находится в радиусе `npc.rodion`
  (30,52).
- Порог: **`T_hold = 6,0 с`** непрерывного удержания.
- Формула прогресса: `holdProgress += Δt`, пока `E` зажата и игрок в
  радиусе; как только `holdProgress ≥ 6,0` — исход `spas` фиксируется
  немедленно (не дожидаясь конца `T_scene`).
- **Отпустил раньше времени — прогресс сбрасывается в 0, а не
  сохраняется.** Решение осознанное: удержание = «держать интеракцию до
  завершения» дословно из §7, а не накопительный прогресс — это самая
  простая и самая честная модель («держишь — тащишь, отпустил — начинай
  заново»), не требует системы «затухания» прогресса (лишняя сложность,
  которую сложнее протестировать). Выход игрока за радиус `npc.rodion`
  тоже сбрасывает `holdProgress` в 0 (логически то же самое, что
  отпустить клавишу — герой отошёл от Родиона).
- Если `E` зажата, а до конца `T_scene` остаётся меньше, чем нужно для
  добора порога (`t_remaining < 6,0 − holdProgress`), спасти уже
  физически нельзя — таймер выигрывает первым, см. §11.5. Это осознанное
  давление: чтобы гарантированно успеть, начать держать `E` нужно не
  позже отметки `t_remaining ≈ 6–9 с` (с учётом времени на дойти от
  `trigger_t4` до Родиона по грудь в воде).

### 11.4 Исход «Снять ключ» (`klyuch`) — нажать F

- Действие: **однократное нажатие** отдельной клавиши `F` (не `E`),
  пока игрок в радиусе `npc.rodion`. Отдельная клавиша, а не «короткое
  нажатие E», сознательно — чтобы не путать «начал держать E и не
  дотерпел» с «выбрал снять ключ»: это два разных решения игрока, не
  один и тот же ввод с разной длительностью.
- Не мгновенно и не требует времени наравне со спасением: короткое
  **фиксированное действие `T_snap = 1,5 с`**, во время которого выбор
  уже необратимо принят (нажатие `E`/`F` в эти 1,5 с игнорируется —
  действие уже «в процессе», герой физически срывает цепочку). Отдельно
  от порога-цифры важно: если `F` нажата **до** истечения `T_scene`
  (пусть даже за 0,1 с до нуля), действие `klyuch` гарантированно
  доигрывает свои 1,5 с до конца — таймер не обрывает уже начатое
  действие на середине (иначе сцена выглядела бы сломанной: герой должен
  либо не успеть начать, либо успеть закончить, но не зависнуть в
  анимации).
- Нажатие `F` в любой момент, включая во время незавершённого удержания
  `E`, немедленно сбрасывает `holdProgress` в 0 и запускает `klyuch` —
  однозначный приоритет последнего решения игрока.

### 11.5 Что происходит, если игрок не успел ничего

Жёсткая, без подвисаний: **автоматически фиксируется исход `klyuch`** —
Родион уходит под воду, латунный ключ падает рядом, герой рефлекторно
хватает его. Логика едина для двух триггеров, какой сработает раньше:

1. `t_remaining` достигает `0` без завершённого `spas`/`klyuch`, либо
2. ~~игрок физически доходит до `trigger_t5` (30,54), не разрешив сцену~~
   — **реализовано только через п.1.** При реализации (OF-049,
   `gameplay-programmer`) выяснилось: `trigger_t5` (30,54, радиус 3) и сам
   Родион (30,52) стоят так, что радиус триггера уже накрывает точку, где
   игрок обязан находиться для интеракции (расстояние 2 ≤ 3) — буквальная
   реализация п.2 форсила исход `klyuch` в момент простого подхода к
   Родиону, раньше, чем игрок успевал нажать `E`/`F` (баг, пойманный
   `tests/e2e/rodion-scene.spec.ts`). П.1 (таймер 15с, не зависит от
   позиции игрока) уже полностью закрывает требование «сцена не должна
   зависать» без п.2, поэтому п.2 из кода убран — `trigger_t5` продолжает
   штатно ставить `flag.truba.zone_e_closed` через свой собственный эффект
   в `truba.json`, просто больше не форсит исход сам по себе.

В обоих случаях применяются те же эффекты, что и у осознанного `klyuch`
(`setFlag flag.prolog_vybor = klyuch`, `giveItem
item.quest_klyuch_shlyuza`), плюс **дополнительный флаг
`flag.truba.choice_timeout = true`** (новый, необязательный для
базового скоупа OF-024, но дёшев в реализации через тот же
`applyEffects`) — исключительно чтобы `narrative-writer` при желании мог
позже различить в репликах Зои «ты выбрал ключ» и «ты не успел», не
меняя сам `flag.prolog_vybor` и не трогая условия концовок в
`main-quest.md`.

`trigger_t5`, помимо возможного форс-резолва по п.2, всегда (при любом
исходе) ставит уже существующий `flag.truba.zone_e_closed = true` и
глушит дальнейшую интеракцию с `npc.rodion` — повторно войти в сцену
нельзя, ровно как описано в §7 («точка невозврата 0»).

Сопровождение Родиона по карте после успешного `spas` (компаньон идёт за
игроком дальше по Трубе) — вне скоупа этой спеки; для вертикального
среза достаточно, что при завершении `spas` NPC помечается как
спасённый и не отображается как «застрявший» (техническое решение —
`gameplay-programmer`, полноценная система компаньонов не нужна для
этой сцены).

### 11.6 Решение game-designer: исход `oba` вырезан в этой волне

**Вырезаю `oba` из вертикального среза.** Обоснование:

1. **Сам P1 из трёх рецензий — про отсутствие давления времени у
   `spas`/`klyuch`, не про третий исход.** Добавление `spas` (держать 6 с)
   и `klyuch` (снять ключ, 1,5 с, другая клавиша) уже полностью закрывает
   рецензируемую проблему; `oba` — не требуемое дополнение, а рост
   скоупа.
2. **`oba` физически противоречив на уровне уже написанного нарратива.**
   `main-quest.md` §2 (Q2) описывает `spas`/`oba` → дорога на Плотину,
   `klyuch` → дорога в Гаражи — это два разных маршрута продолжения
   пролога. Куда ведёт `oba`, если он одновременно «спас» и «взял
   ключ», сам `main-quest.md` не решает (там `oba` только для рычага
   репутации Q2, не для маршрута). Раньше чем это разрешит
   `narrative-writer`/`producer`, вводить `oba` в механику — плодить
   двусмысленность, а не давать честный выбор.
3. **Простота реализации и тестирования.** `oba` потребовал бы
   отдельного порога «успеть и то, и другое за 15 с» (снять ключ за
   1,5 с и затем всё равно удержать 6 с — арифметически укладывается,
   но такой третий путь тестирования (совмещённая последовательность
   двух действий в одном забеге) увеличивает матрицу QA в полтора раза
   ради одной необязательной ветки).
4. Механика построена так, что добавить `oba` позже — тривиально (если
   `klyuch` завершился успешно и *затем* игрок всё равно успевает
   удержать `E` 6,0 с до T5 — можно на следующей итерации просто
   заменить итоговый `setFlag` на `oba` вместо перезаписи поверх
   `klyuch`). Решение не блокирует будущее расширение, только
   откладывает его — по аналогии с решением продюсера по арту
   (`docs/BACKLOG.md`): скоуп сужается, не выдумывается «умная система»
   без запроса.

### 11.7 HUD — конкретные строки

Рендер сейчас — текстовая строка поверх канваса (как существующая
`" | Вода поднимается"` по флагу `flag.truba.water_rising`,
`src/game/demo-scene.ts:621`). Давление времени должно читаться из
текста и цифр, без визуальных эффектов воды:

| Состояние | Условие | Текст на HUD |
|---|---|---|
| Сцена началась, ничего не нажато | `choice_scene_started && !zone_e_closed`, ни один исход не завершён | `Родион тонет: {t_remaining}с — E держать, чтобы вытащить. F — сорвать ключ и уйти.` |
| Идёт удержание `E` | `holdProgress > 0` | `Тащишь Родиона… {holdProgress}/6с. Не отпускай!` |
| Отпустил раньше времени | сразу после сброса `holdProgress` в 0 (показывать ~1 с, затем вернуться к базовой строке) | `Не удержал! Родион дёрнулся под водой — начни заново.` |
| Идёт снятие ключа | `F` нажата, `T_snap` не истёк | `Срываешь цепочку с шеи Родиона…` |
| Исход `spas` | сразу после завершения | `Родион свободен. Тащишь его наверх, к воздуху.` |
| Исход `klyuch` (осознанный) | сразу после завершения | `Латунный ключ у тебя. Родион уходит под воду.` |
| Исход по таймауту | `flag.truba.choice_timeout == true` | `Вода сомкнулась над Родионом. Ключ остался зажат у тебя в кулаке.` |

Числа `{t_remaining}` и `{holdProgress}` — целые секунды (`ceil`/`floor`
соответственно, чтобы таймер не показывал `0` раньше, чем истёк, а
прогресс удержания не показывал `6` раньше, чем реально набран).

### 11.8 Правки в `public/data/dialogs/prolog-vybor.json`

Текущий файл — обычное диалоговое меню на два пункта без таймера, что и
есть корень P1. С новой механикой открытие диалога Родиона по `E`
**убирается** — сцена больше не модальный диалог, а real-time
интеракция поверх геймплея (см. §11.2). Реплики Родиона остаются
текстом, который показывается как часть HUD/оверлея в момент старта
сцены и в момент исхода, а не как узел диалогового графа с `choices`.
Точная разметка JSON/переход на другую схему данных — решение
`gameplay-programmer`/`narrative-writer`, здесь только черновик реплик в
уже заданном тоне (короткие, ≤2 строки, как у прочих реплик Родиона):

- Старт сцены (по `trigger_t4`, разово): «Эй! Эй, стой! Решётку заклинило,
  меня зажало — вода прибывает!»
- Во время удержания (после начала `spas`, один раз): «Тащи, тащи! Ещё
  чуть-чуть!»
- Успех `spas`: «Живой… живой я. Не забуду, слышишь?»
- Успех `klyuch` (осознанный, игрок нажал `F`): «Ключ… возьми. Тону! Хоть
  ключ… возьми…»
- Таймаут (никакой реплики от Родиона — он уже под водой; звучит только
  строка нарратора из §11.7 таблицы): без реплики `npc.rodion`, только
  `speaker: "narrator"`.

Финальный текст, тон и точная реализация — задача `narrative-writer`;
это черновик для программиста, чтобы не блокировать реализацию таймера
ожиданием отдельной итерации нарратива.
