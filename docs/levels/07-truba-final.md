## 0. Формат схемы

Карта **44×32 тайла**, меньше типового хаба Акта 1/2 — сознательное
решение: это не хаб для исследования, а компактная финальная арена.
Ось `x`: 0 (запад, секретная ниша) → 43 (восток, зал арены); ось `y`: 0
(север, арена вокруг задвижки) → 31 (юг, вход/выход к Плотине). 1 симв.
ASCII = 2×2 тайла. Ширина проходов ≥4 тайла, арена — открытая
прямоугольная заливка с двумя точечными колоннами-укрытиями (без
диагоналей).

### Легенда

| Символ | Значение |
|---|---|
| `#` | стена / непроходимая клетка |
| `.` | пол, проходимо |
| `S` | точка спавна героя (по факту — зона сбора B; `findSpawnPoint` берёт центр карты, см. §7) |
| `P` | Палыч (`npc.palych_final`) — Прогресс-2, если Палыч жив |
| `G` | Гриня (`npc.grinya_final`) — Прогресс-2, если Палыч мёртв (`flag.palych_ubit`) |
| `Z` | Зоя (`npc.zoya_final`) — Энергосбыт |
| `D` | Доктор Соломин (`npc.doctor_solomin_final`) — Чистые |
| `V` | Веденеев (`npc.vedeneev_final`) — опционально, если жив |
| `C` | колонна-укрытие в арене (декор/препятствие, 2×2) |
| `!` | спавн `enemy.boss_zadvizhka` (в самой задвижке) |
| `1` | триггер `trigger_final_gathering` |
| `2` | триггер `trigger_naryad_knizhka_final` (секрет) |
| `X` | секрет — наряд-книжка Палыча, запись Р-0 |
| `>` | выход `exit_to_plotina` |

## 1. Общая схема (1 симв. = 2×2 тайла)

Композиция — «замочная скважина»: узкий подход от Плотины (юг) выводит
в широкую зону сбора (B, все NPC финальной сцены), из которой два
параллельных прохода — центральный (короткий, прямой) и западный
катран-обход (высотная/фланговая позиция) — ведут в арену вокруг самой
задвижки (C, боевая кульминация).

```
y00 ######################
y02 #####............#####   <- арена (C): задвижка в центре, две колонны-укрытия
y04 #####............#####
y06 #####.....##.....#####
y08 ####.............#####
y10 ##...............#####   <- центральный проход арена<->зона сбора
y12 ##...............#####
y14 ##...............#####
y16 ##................####   <- зона сбора (B): все NPC финальной сцены
y18 #.................####
y20 #.................####
y22 #.................####
y24 ##................####
y26 #########....#########   <- подход от Плотины (юг)
y28 #########....#########
y30 #########....#########
```

Левая колонна (`x 4–9`) на строках `y08–y24` — западный катран-обход
(вне показанной сетки выше из-за смещения, см. зону D ниже); секретная
ниша (`x 3–8, y18–23`) примыкает к зоне сбора с запада.

### Зона A — Подход от Плотины, `x 18–25, y 26–31`

`>` (21,29) — `exit_to_plotina`. Единственный вход/выход карты (с
Плотины сцена буквально «спускается» к задвижке — `main-quest.md` §1
«Плотина → Труба»).

### Зона B — Зона сбора (NPC финальной сцены), `x 8–35, y 16–25`

```
y16 ####################
y18 #..................#
y20 #..P....Z........D.#     P (12,20), Z (20,20), D (28,20)
y22 #..G..............V#     G (12,23), V (28,23)
y24 #..................#
```

Пять NPC-заглушек финальной сцены (см. §7 про глобальную уникальность
id и трактовку «4 стороны»), `1` (21,20) — `trigger_final_gathering`,
анкер для будущей сценарной завязки диалога перед боем. Здесь же —
предбоевой лут (аптечка/патроны, §5) у входов в арену.

### Зона C — Арена (главная задвижка), `x 10–33, y 2–15`

`!` (21,8) — `spawn_boss_zadvizhka`. Две колонны-укрытия `C` (15–16,6–7)
и (26–27,6–7) — минимальное прикрытие от AoE-залпа (радиус 3 тайла,
combat.md §2.8), не загораживающее обзор на саму задвижку (телеграф
залпа читается из любой точки открытой арены).

### Зона D — Западный катран (нелинейный/фланговый путь), `x 4–9, y 8–25`

Второй, узкий (≥5 тайлов) проход из зоны сбора в арену, параллельный
центральному. Тактически читается как приподнятый над машинным залом
служебный катран (высотная точка боя — `combat.md` требует высотные
точки и укрытия для боя) — вход в арену с запада, а не строго с юга,
даёт игроку позицию для фланкирования штока задвижки, когда тот
открывается после залпа (`weakness.window: 'cooldown-start'`, 2 с).

### Зона E — Секрет: наряд-книжка Палыча, `x 3–8, y 18–23`

`2` (5,20) — `trigger_naryad_knizhka_final`. Найденная здесь
предполагаемая запись — тот самый наряд Р-0 («на полчаса, по
регламенту, на треть») с признания «Я кран» (`main-quest.md` §2 Q2),
только теперь герой видит документ своими глазами в финале, у самой
задвижки — кольцевая композиция сюжета.

## 2. Темп и чередование

| Блок | Зона | Тип темпа |
|---|---|---|
| Подход | A | Переход |
| Зона сбора | B | Диалог (сцена перед боем, NPC по `flag.storona`) |
| Секрет | E | Исследование (опционально, без боя) |
| Арена | C (+ D как обход/фланг) | Бой (финальный босс) |

Вся карта — одна сцена «диалог → бой», без повторов; секрет — опциональная
пауза между ними, не превращающая переход в третий тип темпа подряд.

## 4. Спавны врагов

| ID | Враг | Позиция | Кол-во | Комментарий |
|---|---|---|---|---|
| `spawn_boss_zadvizhka` | `enemy.boss_zadvizhka` | (21, 8) | 1 | 400 ХП, AoE «водяной залп», шток — слабость `×3, игнорирует броню`, окно 2 с после атаки (combat.md §2.8) |

**Почему босс уместен именно здесь.** Главная задвижка — не абстрактная
арена, а сам сюжетный объект: заклинивший в Р-0 механизм, который
тридцать лет «стоит» (`world-bible.md` §2.1). Финальное действие игрока
(`flag.truba_deystviye`) физически исполняется именно на нём. Трактовка
level-designer: тридцать лет простоя + наконец-то приложенное усилие
(открыть/закрыть/взорвать/передать под тариф) физически «пробуждают»
изношенный механизм — водяной удар, разгерметизация, автоматика
безопасности идут вразнос. Бой с Боссом-задвижкой — это и есть игровое
исполнение финального выбора, а не отдельный «геймплейный босс сбоку от
сюжета»: NPC-лидер стороны приводит героя к задвижке (зона B), а сама
задвижка (зона C) — последнее физическое препятствие между игроком и
`flag.truba_deystviye`, независимо от того, какую сторону выбрал
игрок. Это отличет его от «повествовательного» финала (разговоры с
NPC, которые определяют исход) — Босс-задвижка не конкурирует с
`flag.storona` за место антагониста — он возникает уже после того, как
решение принято, как физическая цена его исполнения.

## 6. Секрет и нелинейный путь

**Секрет.** Наряд-книжка Палыча (зона E) — кольцевая деталь
окружения, без боя и без нового лута (только флаг для будущей
реплики/эпилога).

**Нелинейный путь.** Западный катран (зона D) — второй проход в арену,
параллельный центральному; функционально даёт игроку позиционный
выбор (фланг vs прямой подход) перед боем, а не обход самого боя (босс
неизбежен для завершения сцены) — тактическая, а не сюжетная
развилка, что уместно для финальной арены.

## 7. Связь с флагами `main-quest.md` и трактовка «4 стороны»

`main-quest.md` §2 Q6: «Ключевые NPC. Зависит от `flag.storona`:
Палыч/Гриня, Зоя, Соломин; Веденеев (если `flag.vedeneev_sudba ≠ mertv`)
может появиться». Полноценного переключения NPC по игровому флагу в
движке ещё нет (то же ограничение, что и `flag.rodion`/дублирование id
между картами, `03-plotina.md` §7) — **и `npc.palych`/`npc.zoya` уже
заняты на `map.garazhi`/`map.plotina`, их id нельзя переиспользовать
здесь** (`tools/validate-data.ts` требует глобальной уникальности id
NPC). Трактовка level-designer, тот же приём, что и `npc.rodion_plotina`
в задаче на будущее из `03-plotina.md`: пять отдельных id
«финальной сцены» —

- `npc.palych_final` / `npc.grinya_final` — Прогресс-2 (ровно один из
  двух реально появится в диалоге, в зависимости от `flag.palych_ubit`;
  оба физически размещены и достижимы здесь);
- `npc.zoya_final` — Энергосбыт;
- `npc.doctor_solomin_final` — Чистые;
- `npc.vedeneev_final` — опциональный участник/противник независимо от
  `flag.storona` (см. main-quest.md §2 Q6).

Карта физически размещает и делает достижимым представителя каждой из
трёх фракционных сторон плюс опционального Веденеева. Исход
`neytralitet` не требует отдельного NPC (`main-quest.md` §2 Q6 —
«герой действует один») — он уже покрыт тем, что сама арена и выход
достижимы без каких-либо условных NPC. Реальное условное появление
**ровно одного** NPC по значению `flag.storona` в момент сцены — задача
диалоговой системы Акта 3 (OF-036) и переключения карт
(gameplay-programmer), вне скоупа OF-037; здесь зафиксирована
физическая ёмкость карты, доказанная тестом
(`tests/unit/game/world/act2-3-maps.test.ts`, раздел «все 4 исхода
`flag.storona`»).

`S` — как и на остальных картах, отдельного поля точки спавна игрока
`MapSchema` не описывает; с реальным переключением карт (OF-051,
`demo-scene.ts: switchMap`/`resolveEntryPoint`, живая проверка —
`tests/e2e/act2-3-transition.spec.ts`) вход с Плотины высаживает героя на
«зеркальном» exit — `exit_to_plotina` (21,29), в самом начале подхода
(зона A), а не сразу в зоне сбора — герой видит короткий подход, потом
NPC финальной сцены, что не портит темп (§2). `findSpawnPoint` (центр
карты, зона сбора, `(22,16)`) остаётся фолбэком только для прямого
захода `?map=truba_final`.

## 8. Читаемость и проверка по требованиям задачи

- **Нелинейный путь**: западный катран, тактический обход/фланг арены (§6).
- **Секрет**: наряд-книжка Палыча (§6).
- **Главный конфликт локации**: решение игрока (`flag.storona` +
  финальное действие) против физического сопротивления самой
  тридцатилетней задвижки — бой не конкурирует с сюжетным выбором, а
  является его ценой (§4).
- **История в декорациях**: заклинившая тридцать лет задвижка, кольцевая
  находка наряд-книжки — тот же плакат/тема из `world-bible.md` §2.1,
  теперь увиденная в финале, а не в прологе.
- **Чередование темпа**: см. §2 — диалог → (опционально исследование) →
  бой, ровно один переход каждого типа.
- **Ширина проходов / без диагоналей**: ≥4 тайла на всех соединяющих
  коридорах и в арене; колонны-укрытия — точечные заливки 2×2.
- **Проверка проходимости**: `tests/unit/game/world/act2-3-maps.test.ts`
  — BFS от спавна подтверждает достижимость всех пяти NPC, спавна
  босса, обоих триггеров, лута и выхода; отдельный тест проверяет
  физическую ёмкость карты для всех 4 исходов `flag.storona`. Живьём
  (реальный движок) — `tests/e2e/act2-3-transition.spec.ts` подтверждает
  переход Плотина↔Труба-финал, что Босс-задвижка жив сразу после
  загрузки карты и что герой физически достигает всех пяти позиций NPC
  финальной сцены без ошибок.
