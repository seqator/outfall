## 0. Общие решения для всех трёх карт

### 0.1 Ограничение по доступным врагам — важно для будущей волновой системы

`combat.md` §2 описывает 8 типов врагов, но на момент этой задачи в
`public/data/enemies.json` зарегистрировано только **5**:
`enemy.raki` (рашер), `enemy.podlineiny` (контролёр),
`enemy.krysa_plastikovaya` (рашер-свара), `enemy.avtomat_nii` (турель),
`enemy.boss_zadvizhka` (босс). Формулы для `enemy.ohrana_progress2`
(стрелок), `enemy.energosbytovets` (элита) и `enemy.chisty` (метатель)
уже есть в коде (`src/sim/formulas/enemies.ts`), но записей в
`enemies.json` для них нет — `map.enemySpawns[].enemyId` обязан
ссылаться на существующую запись (`tools/validate-data.ts`), поэтому
использовать эти три врага в картах Арены сейчас нельзя, не расширяя
`enemies.json` (вне скоупа этой задачи — только `maps/arena_*.json` +
этот документ).

**Следствие для дизайна**: ни одна из трёх карт не может предложить роли
«стрелок», «элита», «метатель» — только рашер (ближний), контролёр
(обездвиживание), рашер-свара (числом), турель (стационарный дальний) и
босс (капстоун). Три карты ниже спроектированы так, чтобы этот дефицит
ролей был не заметен: «Яма» строится вокруг рашера/контролёра (роли,
которые и не нуждаются в стрелке), «Двор» и «Разлив» компенсируют
недостающего «стрелка»/«элиту» турелью (`enemy.avtomat_nii`) как
единственным доступным источником дальнего давления. Когда
`enemy.ohrana_progress2`/`enemy.energosbytovets`/`enemy.chisty` попадут
в `enemies.json` (отдельная будущая задача), у всех трёх карт уже есть
зарезервированные позиции у стен/точек обзора, которые можно
конвертировать под них без переделки геометрии — см. пометки «зарезервировано
под будущего стрелка» в §2–4.

### 0.2 Формат «волновой пул», а не «10 списков»

`MapSchema.EnemySpawnSchema` не имеет поля «волна» — это плоский список
точек. Числовая кривая нарастания волн (сколько врагов на волне N,
какой темп) — решение game-designer/gameplay-programmer при реализации
самой системы волн (не в этом документе, см. предупреждение в шапке).
Здесь каждая карта резервирует **пул точек спавна**, размеченный по
`id`-суффиксу на 4 условных яруса сложности:

| Ярус | Суффикс id | Условно волны | Смысл |
|---|---|---|---|
| T1 | `_t1_*` | 1–3 | лёгкий вход, знакомство с ареной |
| T2 | `_t2_*` | 4–6 | добавляется второй тип угрозы (контролёр/турель/свара) |
| T3 | `_t3_*` | 7–9 | все типы угроз карты одновременно, темп жёстче |
| T4 | `_t4_*` / `_boss` | 10 (финал) | капстоун — самая плотная волна или босс |

Будущая система волн вольна брать из яруса не всё сразу (типично —
подмножество точек на волну, растущее по номеру волны внутри яруса);
пул закладывает достаточный запас позиций, чтобы 10 волн не повторяли
одну и ту же геометрию боя. Это тот же принцип, которым уже
руководствовались `05-sanatoriy.md`/`03-plotina.md` для группового
спавна («3–5 крыс» — несколько отдельных записей `enemySpawns[]», не
`count`, — известное ограничение движка, `count` пока не даёт
групповой спавн, см. `04-paneli.md`/`OF-037`).

### 0.3 Выход — временно на `map.garazhi`, не «в меню»

`MapExitSchema.toMap` обязан указывать на существующий `map.*`; в игре
пока нет отдельной «карты-меню» — экраны (титульник, меню) не являются
`GameMap`. До того как код-часть OF-039 подключит реальный запуск Арены
из UI-меню (не через `exits[]`, а отдельным экраном выбора карты — то
же решение, каким сейчас открывается основная кампания), каждая из
трёх карт получает **ровно один** `exit` — назад, на `map.garazhi`
(центральный хаб кампании, уже связанный с остальным графом,
`OF-033`). Это временный, физически рабочий «выход со полигона» на
случай прямого захода по `?map=arena_1` (тот же паттерн отладки, что и
у всех остальных карт), а не финальный UX запуска Арены — тот определит
gameplay-programmer. Обратного ребра `map.garazhi → map.arena_*` в этой
задаче намеренно не добавлено (не трогаем существующий `garazhi.json`,
вне списка разрешённых файлов задачи); реальный вход в Арену — кнопка
в меню, не физическая дверь на карте.

### 0.4 Модификаторы

Оба модификатора концепта («без рывка», «только ножи») — правила,
применяемые к самому игроку (блокировка ввода/оружия), не к геометрии
карты. Карты ничего не резервируют под них специально: «Яма» уже
достаточно тесна, чтобы «только ножи» имело смысл, «Разлив» уже
достаточно открыт и дальнобоен, чтобы «без рывка» ощущался опасным —
но это следствие уже заложенного контраста площадок, а не отдельная
доработка.

### 0.5 Общая легенда карт

| Символ (ASCII-схемы ниже) | Значение |
|---|---|
| `#` | стена / непроходимая клетка, коллизия 1 |
| `.` | пол, проходимо |
| `S` | точка спавна героя (`findSpawnPoint` — центр карты, на всех трёх картах он свободен) |
| `C` | колонна/пилон-укрытие (декор-препятствие, точечная заливка) |
| `>` | выход `exit_*_out` → `map.garazhi` |

ASCII-схемы — обзорные, **1 символ = 2×2 тайла** (тот же масштаб, что
`02-garazhi.md`/`07-truba-final.md`); координаты в таблицах спавнов —
реальные тайлы, источник истины для контента. Все стены/укрытия —
прямоугольные заливки, ни одной диагональной «лесенки» под 45°; ширина
основных проходов ≥5 тайлов на «Дворе»/«Разливе», ≥4 на компактной
«Яме» (сама арена — открытая заливка, не коридор), второстепенные
проходы (фланговый коридор-тайник) — 3–4 тайла, тот же допуск, что и
хабовые аппендиксы `02-garazhi.md` §0.

## 1. Арена I — «Яма» (`map.arena_1`, 22×22)

Маленькая тесная площадка для ближнего боя: рашеры (`enemy.raki`) и
контролёры (`enemy.podlineiny`) со временем разбавляются свара-крысами
(`enemy.krysa_plastikovaya`). Ни одной дальнобойной угрозы — «Яма»
целиком про позиционирование в тесноте, рывки между четырьмя пилонами и
чтение телеграфов клешни/сети практически в упор.

**Цель игрока.** Продержаться как можно больше волн в замкнутом ринге,
не давая рашерам и контролёрам зажать в углу.

**Главный конфликт.** Теснота: 4 симметричных пилона-укрытия дробят
единственный открытый зал на диагональные сектора обзора — рашер,
подошедший из «слепого» относительно текущей позиции игрока сектора,
читается только в последний момент (сам пилон не прячет врага
полностью — противоположная сторона видна из соседнего сектора, но не
из текущей позиции игрока, поэтому нельзя стоять на месте).

### 1.1 Схема (1 симв. = 2×2 тайла)

```
y00 ###########
y02 #.#.......#
y04 #.##...##.#
y06 #.##...##.#
y08 #.#.......#
y10 #.#...S...#
y12 #.#.......#
y14 #.##...##.#
y16 #.##...##.#
y18 #.#.......#
y20 ###########
```

Открытый зал `x1–20, y1–20` (реальные тайлы) с 4 пилонами 2×2
(`x5–6,y5–6` / `x15–16,y5–6` / `x5–6,y15–16` / `x15–16,y15–16`) и
узким (3 тайла) фланговым коридором вдоль западной стены (`x1–3`,
столбец-разделитель `x4`), см. §1.3. `S` — точка спавна героя, центр
карты `(11,11)`, всегда свободна.

### 1.2 Темп и чередование

| Блок | Тип темпа |
|---|---|
| Заход, волны 1–3 (T1) | Бой, лёгкий — знакомство с ареной |
| Волны 4–6 (T2), между волнами — осмотр тайника | Бой + короткое исследование (фланговый коридор) |
| Волны 7–9 (T3) | Бой, плотнее |
| Волна 10 (T4), финальный свара-рой | Бой, кульминация |

Между волнами игрок физически успевает пробежать к пилону/тайнику —
но карта не заставляет останавливаться дольше 90 с в одном режиме,
так как исследование ограничено самим размером арены (тайник — 5–10 с
крюк, не отдельный уровень).

### 1.3 Секрет и нелинейный путь

Оба реализованы одной геометрией — фланговый коридор вдоль западной
стены (`x1–3, y1–20`), отделённый от основного зала стеной-столбцом
`x4` с двумя проходами (по 2 тайла) — на севере `y3–4` и на юге
`y17–18`. Коридор целиком в стороне от всех точек спавна волн (§1.5) —
пробежать по нему можно, не встретив ни одного врага «в лоб».

- **Нелинейный путь**: коридор соединяет северную и южную половины
  арены в обход центра с пилонами — тактический фланг, чтобы не
  пересекать открытый зал по прямой под обстрелом со всех точек
  спавна одновременно.
- **Секрет**: в середине коридора (недоступной ни с одного из двух
  входов без прохода через весь коридор) — тайник с ломом,
  `pickup_secret_scrap_yama_a`/`_b` (§1.6). Тайник открыт геометрически
  (тот же принцип, что бокс «2207» в `02-garazhi.md` §6), без замка.

### 1.4 История в декорациях

«Яма» читается как бывший приямок технического колодца, наспех
приспособленный под кулачный ринг — четыре пилона держали перекрытие,
которого больше нет (крыши нет — открытый ринг). Деталь для будущего
худа/арт-прохода (не в этой задаче, заблокировано решением о
арт-пайплайне, тот же статус, что `OF-034`/`OF-038`): меловая разметка
ставок прямо на полу вокруг центра.

## 2. Арена II — «Двор» (`map.arena_2`, 34×30)

Средняя площадка гаражного двора с укрытиями (штабеля/боксы) —
классический «бой на позициях» из `combat.md` §1: рашеры и контролёры
приходится продавливать между блоками укрытий, а с 4-й волны в дело
вступает стационарная турель (`enemy.avtomat_nii`), которая держит под
прицелом центральные проходы и заставляет использовать укрытия не
только против рашеров, но и против дальнего луча.

**Цель игрока.** Пережить волны, используя 6 блоков укрытий, чтобы
разорвать одновременный прицел турелей и напор рашеров с флангов.

**Главный конфликт.** Перекрёстный огонь: с 7-й волны в игре сразу
**две** турели (западная и восточная стены) — любое открытое
пересечение центра арены простреливается с двух сторон, укрытия в
центре (`x14–15`/`x19–20, y13–17`) — единственная безопасная линия
подхода.

### 2.1 Схема (1 симв. = 2×2 тайла)

```
y00 #################
y02 #...............#
y04 #...............#
y06 #..##.......##..#
y08 #..##.......##..#
y10 #..##.......##..#
y12 #......#.##.....#
y14 #......#.##.....#
y16 #......#.##.....#
y18 #..##.......##..#
y20 #..##.......##..#
y22 #..##.......#####
y24 #.............#.#
y26 #.............###
y28 #################
```

4 угловых блока-укрытия (`x6–8,y7–10` / `x25–27,y7–10` /
`x6–8,y19–22` / `x25–27,y19–22`) + 2 центральных (`x14–15,y13–17` /
`x19–20,y13–17`), оставляющих открытым сам центр `(17,15)` (спавн
героя). Юго-восточный угол — закрытая комната-тайник (§2.3),
единственный вход — 2-тайловая дверь с севера.

### 2.2 Темп и чередование

| Блок | Тип темпа |
|---|---|
| Волны 1–3 (T1) | Бой, знакомство с укрытиями |
| Волны 4–6 (T2) | Бой + первая турель (запад) |
| Между волнами | Исследование (тайник в юго-восточном углу) |
| Волны 7–9 (T3) | Бой, вторая турель (восток) — перекрёстный огонь |
| Волна 10 (T4) | Бой, кульминация — обе турели + плотный ближний бой |

### 2.3 Секрет и нелинейный путь

**Секрет.** Закрытая комната `x29–31, y23–26` в юго-восточном углу,
единственный вход — 2-тайловая дверь на северной стене (`x29–30,

## 3. Арена III — «Разлив» (`map.arena_3`, 50×42)

Большая открытая площадка у берега — самая протяжённая карта, дающая
дальнобойным угрозам (обеим турелям `enemy.avtomat_nii`) полноценный
простор для стрельбы через всё поле, а на 10-й волне выпускающая
`enemy.boss_zadvizhka` (единственный доступный «раид-босс» контента,
см. §0.1) в северной нише как капстоун серии — ровно та же боевая

**Цель игрока.** Дожить до 10-й волны и пережить бой с

как редкие точки передышки от AoE-залпа и турельного огня.

**Главный конфликт.** Дистанция: обе турели простреливают почти весь

## 4. Читаемость и проверка по требованиям задачи (все три карты)

- **Нелинейный путь**: на каждой карте — фланговый/обходной коридор,
  физически не пересекающий основные точки спавна волн (§1.3, §2.3,
  §3.3).
- **Секрет**: на каждой карте — тайник в глубине этого же коридора,
  открытый геометрически, без замка (§1.3/1.6, §2.3/2.5, §3.3/3.5).
- **Главный конфликт**: теснота («Яма»), перекрёстный огонь между
  укрытиями («Двор»), простреливаемая дистанция + AoE-босс в финале
  («Разлив») — три разных боевых почерка на трёх картах, как и
  требовалось («разного размера/тактики»).
- **История в декорациях**: §1.4, §2.7, §3.7 — во всех трёх случаях
  явно помечено как рабочая гипотеза level-design для будущего
  арт/нарратив-прохода, не как заявленный канон мира (не входит в
  скоуп этой задачи).
- **Чередование темпа**: §1.2, §2.2, §3.2 — бой чередуется с короткими
  окнами на исследование (тайник) между ярусами волн, ни один блок не
  тянется дольше ~90 с одного типа.
- **Ширина проходов / без диагоналей**: см. §0.5 — все укрытия и стены
  built как прямоугольные заливки; открытые арены не содержат
  диагональных бутылочных горлышек.
- **Индикация врагов**: ни один спавн не спрятан за стеной без
  возможности увидеть телеграф издалека — пилоны/укрытия точечные
  (2×2/3×4), не перекрывают целиком ни один сектор обзора арены;
  турели стоят у стен на открытом поле, видны с любой точки
  соответствующей половины арены.
- **Проверка проходимости**: каждая карта проверена скриптом
  генерации (`scratchpad`, не входит в репозиторий) на полную
  связность (BFS от `findSpawnPoint`: все точки спавна волн, лута,
  выхода и секретного коридора достижимы, ни одной изолированной
  клетки пола) — числа: «Яма» 368/368 клеток пола, «Двор» 812/812,
  «Разлив» 1852/1852 клеток пола связаны в одну область. Постоянного
  юнит-теста в `tests/` для этого не заведено (не в списке разрешённых
  файлов задачи — только `maps/arena_*.json` + этот документ);
  ближайший прецедент такого теста для будущей задачи —
  `tests/unit/game/world/act1-maps.test.ts`.
- **`npm run validate`**: зелёный (`maps=10`, было 7) — см. §5, три
  новых ключа `nameKey` добавлены в `public/data/i18n/ru.json`
  (`map.arena_1.name`, `map.arena_2.name`, `map.arena_3.name`) — это
  единственный файл за пределами `maps/arena_*.json`, который
  потребовалось тронуть, потому что `tools/validate-data.ts` жёстко
  проверяет `map.nameKey → i18n/ru.json` (без этих трёх строк
  `validate` был бы красным на новых картах, что нарушало бы явный
  критерий задачи «`npm run validate` должен остаться зелёным»).
  `npm run build` (579/579 unit-тестов, typecheck, lint, size-check)
  тоже зелёный после правки.
