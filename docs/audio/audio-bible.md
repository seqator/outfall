# OUTFALL — Аудио-библ (v0.1)

> Задача бэклога: OF-001. Источники: `docs/OUTFALL-CONCEPT.md` (мир, §4–5, §9), `docs/BACKLOG.md`.
> `docs/art/art-bible.md` на момент написания ещё не существует (OF-006 не сделан) — палитра звука согласована напрямую с §9 концепта («чистый пиксель, грязный мир», серо-бурый ключ, кислотный акцент) и с боевой системой §5.
> Правило: никакого чужого копирайтного аудио. Все референсы — по духу жанра/инструментария, не по конкретным трекам или исполнителям. Радио-передачи внутри игры звучат на собственные тексты `narrative-writer` (OF-024) — задача аудио здесь только форма (помехи, тембр диктора), не слова.

## 1. Звуковая палитра — общий тон

Мир «Водосброс» растворился, а не сгорел: уцелело только домышленное — чугун, сталь, бетон, стекло, вода. Звук должен быть **мокрым, тяжёлым и электрическим**, без «фэнтезийного» лязга и без чистого хай-тека.

| Слой | Характер | Источник в мире |
|---|---|---|
| Материальный | Бетон, чугун, ржавая сталь: глухие низкие удары, без звона колокольчика | Трубы, решётки, гаражные ворота |
| Влажный | Капель, плеск, гул воды в коллекторе, шипение пара | Труба, Санаторий, водосброс Плотины |
| Электрический | Гул ЛЭП, треск разряда, гудение трансформатора, дребезг люминесцентной лампы | Оголённая линия, Плотина, «Щиток»-интерфейс |
| Радио-помехи | Ламповый шум, свист настройки частоты, обрыв несущей | Диалоговые «бипы», крючки по громкой связи, ambience Трубы |
| Биологический (акцент) | Влажный хитиновый треск, редко и точечно | Раки, штамм-0 |

Общее правило микса: низ (суб-бас/гул) держит атмосферу локаций, середина занята материальными ударами и голосом-бипом, верх — редкие акценты (искра, капля, крит). Кислотный акцент `#B4F02A` из палитры арт-стиля получает звуковую пару — короткий цифровой «щелчок-помеха» на всём, что связано со штаммом и с очевидно «нейросетевым» UI-моментом (см. §4 концепта, мета-шутка про шесть пальцев — звук не педалирует тему, один точечный сигнал на весь срез).

Референсы по духу (не копировать, только направление синтеза): дарк-эмбиент с гитарными фидбэками через ревёрб и delay без атаки медиатора (тянущиеся тона, а не риффы); текстура «глушилки» — несущая частота ГОСТовского радиоприёмника, потерянная в шуме; индустриальный нойз конца 80-х — металл по металлу, конвейерные петли, а не мелодия. Для боя — постпанк/индастриал-бит 120–140 BPM: сухой драм-машинный бас-барабан на четверть, дисторшн-бас восьмыми, минимум мелодии, максимум пульса.

## 2. Музыкальные настроения по локациям среза

Срез — три звуковых пространства: Труба (пролог), Гаражи (хаб Акта 1), Санаторий (Акт 2, для контраста настроения — упоминается для полноты палитры, контент Акта 2 вне вертикального среза). Плюс отдельный **боевой слой**, который накладывается на любую локацию при входе в бой.

### 2.1 Труба — напряжённый эмбиент

- **Дух:** нисходящий гул коллектора, гитарный фидбэк без атаки, тянущийся через долгий ревёрб; радиоволна, которая то ловится, то тонет в шуме.
- **BPM/пульс:** свободный темп, без метра; редкий суб-бас пульс ~50–60 уд/мин как «дыхание трубы» (не бит, а огибающая громкости).
- **Инструментарий для генерации:** синтезированная гитара через гранулярный ревербератор (долгий хвост, фильтр-свип вверх/вниз), белый/розовый шум, пропущенный через полосовой фильтр «радиоприёмник», редкие капли-переливы (короткие FM-звоночки, сильно приглушённые).
- **Динамика:** нарастает при подъёме воды (сценарий 15–25 с концепта) — слой шума воды и лёгкий подъём громкости общего гула, без ударных.

### 2.2 Гаражи — индустриальный пост-панк фоном

- **Дух:** кооператив «Прогресс-2» живёт — где-то стучит молот, работает конвейер; музыка звучит как далёкая репетиция гаражной группы за стеной, приглушённая через бетон.
- **BPM/пульс:** 100–115 BPM, ровный бас-барабан на каждую долю, отфильтрованный «через стену» (срез верхних частот, много низа).
- **Инструментарий для генерации:** синтетический бас (пила/квадрат, лёгкий дисторшн), процедурная перкуссия из семплов металла (удар по трубе, лязг ворот) как замена барабанам, статичный дроновый пэд подложкой.
- **Динамика:** громкость и яркость (открытие фильтра) растут с репутацией/активностью локации — задел на будущее, для среза фиксированный уровень.

### 2.3 Санаторий — тревожный «чистый» звук

- **Дух:** стерильность, которая раздражает больше грязи; чистые синус-тона и колокольная перкуссия на грани консонанса и диссонанса, ощущение больничной тишины с гудением ламп.
- **BPM/пульс:** 70–80 BPM, очень разреженно — доли скорее ощущаются, чем слышны.
- **Инструментарий для генерации:** синус/треугольник пэды с медленным биением (detune 3–7 центов), редкие колокольные удары (FM-синтез, короткий сустейн), тонкий белый шум как «стерильный воздух» вентиляции.
- **Статус:** референс для консистентности палитры; наполнение контентом — фаза 6 (OF-041), вне критерия готовности OF-001/OF-023.

### 2.4 Боевой слой (накладка, не отдельная локация)

- **Дух:** быстрый постпанк/индастриал — сухие драм-машинные удары, дисторшн-бас, никакой мелодии поверх, только пульс и напряжение.
- **BPM:** 120–140 BPM, привязан к интенсивности боя (число живых врагов): нижняя граница — начало боя, верхняя — «шок» (>30 % ХП одним ударом, концепт §5).
- **Интеграция:** кроссфейд 300–500 мс поверх текущей локационной темы при событии `combat:start`, откат к локационной теме через 2 с после `combat:end` без резкого обрыва.

## 4. Пайплайн генерации и обработки

### 4.1 Синтез и генерация

- **Процедурный синтез Web Audio (рантайм или офлайн-рендер тем же кодом).** UI (`sfx.ui.*`), часть оружия (`sfx.weapon.pistol.*`, `sfx.weapon.beam.*`) и диалоговые бипы (`sfx.dialog.beep.*`) собираются из осцилляторов, шумовых буферов и фильтров через `OscillatorNode`/`BiquadFilterNode`/`ConvolverNode` в утилите `tools/audio/synth/` (см. §5 — только служебные утилиты синтеза, не игровая логика). Один и тот же граф с разными параметрами (seed, детюн, длина огибающей) даёт вариации без ручной правки — экономит время и держит единый тембр «Щитка».
- **Генеративные треки для музыки.** Локационные темы (§2) — офлайн-рендер длинных (2–4 мин) луп-подложек через процедурные паттерны (гранулярный ревербератор для гитарных тонов, шумовые фильтры для радио-помех, шаблонный секвенсор для боевого бита). Рендерится один раз в WAV, дальше проходит нормализацию и кодирование — не генерируется в рантайме, чтобы держать детерминированный размер билда.
- **Материальные звуки и окружение** (`sfx.hit.*`, `sfx.step.*`, `sfx.env.*`, `sfx.enemy.*`) — процедурный синтез шумовых импульсов + резонансные фильтры под материал (бетон/металл/плоть/хитин), не запись реальных объектов и не сторонние библиотеки семплов.

### 4.2 Нормализация и формат

- Нормализация: SFX — пик не выше −1 dBTP, интегрированная громкость приводится к общему референсу (−16 LUFS для one-shot, −20 LUFS integrated для музыкальных луп) перед кодированием, чтобы бой не «пробивал» микс музыки.
- Формат: **OGG Vorbis, качество q4** (≈ 96–112 kbps) для всех файлов; моно для SFX и голосовых бипов, стерео только для музыкальных лут и `sfx.env.truba.flow`.
- Лимиты размера: SFX ≤ 100 KB (см. таблицу §3, факт максимум 90 KB), музыкальные треки ≤ 1.5 MB на локацию (критерий OF-023); лупы обрезаются по нулевому пересечению (zero-crossing) на границе, чтобы не было щелчка на стыке.
- Манифест `public/audio/manifest.json` (заполняется в OF-023) перечисляет каждый файл с полями `id`, `event`, `variants[]`, `sizeKb`, `durationMs` — валидируется тем же `npm run validate`, что и остальной контент.

### 4.3 Ленивая загрузка

- Глобальный пакет (`ui.*`, `dialog.beep.*`, оружие игрока) грузится при старте сцены боя/меню — он нужен с первой секунды взаимодействия.
- Локационные пакеты (`env.*`, локационная музыкальная тема, звуки локальных врагов) грузятся при входе в локацию вместе с её ассетами (тот же лоадер, что и тайлсет/атласы, OF-027) и выгружаются при выходе, если память экрана ограничена.

## 5. Интеграция: шина событий, приоритеты, ducking

- **Разделение звука и логики.** Игровые системы (бой, движение, диалог, UI) не знают о `AudioContext` и не вызывают воспроизведение напрямую — они публикуют доменные события через общую `EventBus` ядра (`docs/OUTFALL-CONCEPT.md` §8). Отдельный аудио-слой (`src/audio/`, реализуется в OF-026) подписывается на события и сам решает, какой `sfx.*`/`music.*` id проиграть, какую вариацию выбрать и с каким приоритетом — правило границ слоёв (`core ← sim ← game → render/audio/ui/input/assets`) не нарушается.
- **Приоритеты голосов.** P0 — диалоговые бипы и `ui.confirm`/`ui.error` (никогда не режутся); P1 — оружие и попадания по игроку, музыка; P2 — попадания NPC/врагов друг по другу, шаги, окружение. Лимит одновременных голосов на срез — **24**; при превышении новый звук P2 крадёт голос у самого тихого/старого P2, P0 и P1 не отбираются друг у друга, а мягко ограничиваются числом одинаковых `event.id` одновременно (не больше 4 копий одного и того же попадания разом, чтобы толпа раков не превращалась в кашу).
- **Ducking музыки в диалогах.** При `dialog:open` музыка (локационная тема и боевой слой) приглушается на −8 dB за 200 мс и держится приглушённой, пока открыт диалог; при `dialog:close` — возврат на исходный уровень за 400 мс. Диалоговые бипы всегда звучат поверх приглушённой музыки (P0).
- **Радио и дикторские бипы — без начитки.** Концепт §10 сознательно режет озвучку диалогов; «дипловые» бипы (`sfx.dialog.beep.*`) — это звуковая замена речи по тону канала (нейтральный/враждебный/через помехи), а не произнесённый текст. Слова радио-передач и реплик — зона `narrative-writer` (OF-024), аудио отвечает только за форму несущей и помех.

## 6. Открытые вопросы к OF-023

1. Финальный список трёх оружий среза фиксируется `combat.md` (OF-003) — имена событий `sfx.weapon.*` в этом документе временные placeholder-категории (пистолет/тяжёлое/лучевое), переносятся на реальные ID оружия без изменения структуры.
2. Точное число одновременных SFX-инстансов (24) — гипотеза для среза, подлежит проверке в стресс-сцене 300 врагов / 2000 частиц (риск №3 бэклога, инструментальный тест — на стороне engine-architect).
3. Санаторий и полный саундтрек (OF-041) — вне критерия готовности OF-001, тема зафиксирована для консистентности палитры на будущее.
