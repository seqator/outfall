## 5. Правила спринта

**Как брать задачи**
1. Агент берёт верхнюю задачу со статусом `todo`, у которой все зависимости `done`; приоритет — критический путь из раздела 2.
2. Перед началом агент меняет статус на `in-progress (агент, дата)` в этом файле — одним коммитом, до кода.
3. Один агент — одна задача одновременно. Расширять задачу нельзя; всё лишнее записывается предложением в раздел «Отложено» этого файла, решает producer.
4. В промпт агенту идут только 1–3 файла из колонки «Зависит от» и критерий готовности; не весь репозиторий.

**Что считается done**
1. Критерий готовности из таблицы выполнен буквально и проверяем командой или файлом в репо.
2. `npm run build` зелёный локально и в CI; для задач с контентом — `npm run validate` зелёный.
3. Артефакт лежит в `docs/` или `src/`/`public/`, а не в чате; решения зафиксированы одной строкой в соответствующем документе.
4. Коммит маленький, с сообщением вида `OF-0NN: <что сделано>`, в ветку `claude/outfall-game-concept-73eqjh`.
5. Статус в таблице переведён в `done (хэш коммита)`; если задача породила новую — она не добавляется без снятия другой.

**Когда main считается сломанным**
- Красный любой из: `npm run build`, `npm run validate`, `npm run test:e2e`, `size-check`, FPS < 55 на стресс-сцене в CI.
- Сломанный main — стоп-фактор №1: новые задачи не берутся, пока автор последнего коммита не починит или producer не откатит коммит.
- Починка сломанного main — всегда отдельный коммит, без новой функциональности.
- Три сломанных main за спринт — внеочередная планёрка: сужаем скоуп, а не расширяем время.
